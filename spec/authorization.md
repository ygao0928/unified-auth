# 权限匹配与数据范围规则

三端 SDK 的 `has_perm` / `require_perm` 和 `data_scope` **必须**完全按本文规则实现。一致性测试用例见 [`conformance/vectors/authz-cases.json`](../conformance/vectors/authz-cases.json)。

## 1. 权限点格式

```
<app>:<resource>:<action>
```

- 必须正好包含 **3 段**，用英文冒号 `:` 分隔。
- 每段只能是 `[a-z0-9][a-z0-9_-]{0,63}` 格式的字符串，或者通配符 `*`。
- **区分大小写**。权限点只允许使用小写字母，所以包含大写字母的权限点本身就是非法的。
- 通配符 `*` **只能出现在已授予的权限中**，也就是角色配置里。代码中通过 `require_perm` 声明的"所需权限"不允许包含通配符；一旦包含，SDK 必须抛出编程错误（启动时或调用时都可以），不能当作普通的鉴权失败处理。

正则表达式：

```
授予权限：^(\*|[a-z0-9][a-z0-9_-]{0,63})(:(\*|[a-z0-9][a-z0-9_-]{0,63})){2}$
所需权限：^[a-z0-9][a-z0-9_-]{0,63}(:[a-z0-9][a-z0-9_-]{0,63}){2}$
```

## 2. 匹配规则

`has_perm(required)` 的判定方式：只要用户已授予的权限集合中，存在**任意一个**权限点 `g` 满足"三段逐段比较时，每一段 `g[i] == "*"` 或 `g[i] == required[i]`"，就返回 `true`，否则返回 `false`。

- `*` 只匹配**一整段**，不跨段，也不做前缀匹配。例如 `meeting:*` 只有两段，属于非法授予，SDK 必须忽略它并输出告警日志。
- 已授予集合中的非法权限点，SDK 必须忽略并输出告警日志，不能抛出异常。
- `*:*:*` 表示超级管理员，可以匹配任何合法的所需权限。

### 组合判定

- `require_all([a, b])`：每一项都满足 `has_perm` 时才通过。
- `require_any([a, b])`：任意一项满足 `has_perm` 即通过。
- 列表为空时属于编程错误，SDK 必须抛出异常。

## 3. 数据范围

### 取值，从窄到宽

| 值 | 含义 |
|---|---|
| `self` | 只能访问本人的数据 |
| `dept` | 可以访问本部门的数据 |
| `dept_and_sub` | 可以访问本部门及所有下级部门的数据 |
| `all` | 可以访问全部数据 |

### 合并规则

用户在当前应用下的有效角色，是"全局角色 + 本应用角色"的并集。合并步骤如下：

1. 收集所有有效角色的 `data_scope`，忽略值为 `null` 的角色（`null` 表示该角色不涉及数据范围）。
2. 收集结果为空时，有效数据范围为 `null`，表示不适用。业务代码应当按"不做数据范围过滤"处理，还是按"拒绝访问"处理，由业务自己决定，SDK 不做假设。
3. 收集结果不为空时，取其中**最宽**的一个值。
4. **降级规则**：如果结果是 `dept` 或 `dept_and_sub`，但用户的 `dept_id` 为 `null`，降级为 `self`。

权限中心的 `GET /api/v1/authz/users/{sub}/apps/{app}` 接口返回的是**未经降级**的 `data_scope`，降级由 SDK 根据 token 中的 `dept_id` 完成。这样做的原因是，部门信息以 token 为准，权限中心不一定掌握最新的部门数据。
